# 项目设计与边界

## 数据与划分

`load_dataset` 读取逐行 JSON，以 `(reviewerID, asin)` 去重，优先最新时间，相同时间保留最后一行。用户、商品和记录统一按标识排序，划分索引基于这个规范顺序，原始文件 SHA256 用于校验来源。无效记录明确报错，不静默删除。

外层逐用户 `floor(n×0.8)` 条训练，其余测试，至少一条训练与测试（n≥2）。单记录用户留在训练。内层仅拆外层训练，任何算法的统计量、相似度、偏置、因子均只来自当前训练矩阵。最终模型重新拟合完整外层训练，不重用内层模型状态。

已知目录包含原始数据的全部商品 ID。未在训练中出现的商品保留为候选，模型以基线回退。目录标识的已知不意味着测试评分或评论可用于训练。默认数据中所有用户都有至少五条记录，所有用户都有外层测试记录。

## 模型

均值基线为训练观测评分的均值。Bias 固定均值，交替迭代求解 L2 正则用户偏置和商品偏置，默认 20 轮。

ItemKNN 的残差矩阵在缺失位置填零。相似度分母使用完整残差向量的 L2 范数，共同评分人数使用二值观测矩阵的乘积，再乘收缩系数。负相似度置零，自相似度置零。预测目标商品时，在当前用户已评分的物品中选择至多 k 个最相似商品，不在全目录先截断邻居。相似度为零时使用 Bias。归一化分母为正权重之和。

MFALS 在 Bias 拟合后的残差上交替更新用户与物品因子。单次更新求解 `(QᵀQ+λI)p=Qᵀe` 或对称物品方程，仅汇总该实体已观测的交互。偏置保持固定，因子正则不随交互数缩放。每轮记录实际优化目标，单元测试检查目标单调不增。无交互的商品更新为零因子。

评分查询在模型输出后裁剪到 [1,5]。排序直接使用未裁剪得分，热门基线使用训练观测次数，两者的得分含义在推荐 CSV 中明确标注。所有排序得分必须为有限数。

## 验证与评估

候选网格在 `configs/default.json` 中固定。评分模型按验证 RMSE 选择其参数。先按验证 RMSE 预选评分模型，按验证 NDCG 预选排序模型，写入 `selection.json`，之后才访问测试评分计算指标。

默认网格中 ItemKNN 和 MFALS 的偏置正则固定为 15，独立 Bias 比较 5、15、30。这个范围较小，不声称是全面寻优。排序只在已选择的每个算法配置中比较，没有对所有参数另做排序目标调优。

课程 F-measure 由宏平均 Precision 和 Recall 计算。为方便核验也输出逐用户 F1 的宏平均 `macro_f1`，两者不可混用。NDCG 使用二值相关项，相关集为所有测试商品。候选为全目录减去用户训练历史，未用负采样。

排序评价遍历有测试记录的用户。若迁移到含单记录用户的数据，报告 `evaluated_users` 反映参与排序评价的用户数。推荐不足十项时 Precision 的分母仍为十，本数据有充足候选，因此每用户都输出十项。

## 可复现与产物

独立随机数生成器避免全局 RNG 状态污染。外层 seed=42，内层 seed=43，ALS 使用配置种子。默认 CLI 将未显式设置的 BLAS 线程数设为一，减少小线性系统的线程开销。

模型保存只使用 NumPy 数组与 JSON 标量，加载禁止 pickle。NPZ 包含训练历史掩码、ID 映射和推断必需的参数，可直接复用。最终模型保持离线评估状态，未把测试记录加入训练。

稠密训练矩阵约 13 MB，物品相似度约 7 MB；算法适合当前小型 5-core 数据。扩展到百万交互规模需重构为稀疏实现。运行时间与性能指标分开存储，时间不保证跨机器一致。

## 局限

随机划分不是时间外推；单随机种子的结果没有显著性保证；训练评分次数只是受欢迎程度代理；测试商品也包含低星评分；无元数据无法可靠展示商品名称和图片。报告基于实测结果，不编造复杂模型优于基线的结论。
